# 续期订单与订阅显示

用户可从「我的订阅 → 续期套餐」或侧栏「订单与续期」提交当前套餐的续期申请。套餐时长沿用后台设置的天数，提交时保存名称、额度、时长和金额快照。没有套餐或没有到期时间的账号不能申请续期；每个账号同时最多一条待确认申请，可自行取消。

管理员在「续期订单」集中处理，也可在「用户管理 → TA 的订单」确认或拒绝该用户的申请。确认后按订单快照分配套餐，生成一条已生效订单。同套餐未到期时从原到期时间顺延，保留本周期用量和月度重置日；已到期后从确认时间重新开通周期。账号套餐已改变、被停用或删除时拒绝确认，需先拒绝旧申请再重新提交。重复提交和重复确认不重复延长。此流程为人工确认，不自动收款。

管理员编辑用户时，可使用「1个月、3个月、半年、1年」快捷按钮。它们按浏览器本地自然月顺延当前到期时间；已到期或未设置则从现在计算，短月份取月末。按钮仅填写日期，保存用户后生效，不修改套餐、用量或订单。

有效订阅在真实节点前加两条信息节点：剩余流量（GB = 1,000,000,000 字节）与有效期（面板 `TZ`，无期限显示长期有效）。它们完整复制第一个可用节点的参数，仅名称不同，使用订阅所属账号的凭据。流量及期限在客户端更新订阅时刷新，标准 `Subscription-Userinfo` 响应头同时保留。

到期的有效订阅令牌返回一条 Shadowsocks 提示节点「订阅已过期，需要续费」，地址 `127.0.0.1:65535`，不包含真实节点或账号连接凭据。额度耗尽时同样返回「流量已用尽，请续费」。这条节点仅用于替换客户端旧列表，不能提供代理服务。续期后重新更新原订阅即可恢复可用节点。无效令牌、停用或删除账号仍返回 404。

「节点在线情况」用紧凑列表展示节点、状态、服务器心跳、最近自测时间；正常状态要求近期成功结果及在线服务器，离线与过期结果不算正常。仍由服务器自动检测，页面每十五秒刷新。

## 更新与回退

本次只需更新面板，无需更换 v0.1.4-preview 节点二进制。先备份数据库和私有 `.env`，再执行：

```sh
cd /opt/luma
sh scripts/backup.sh && git pull --ff-only && docker compose up -d --build --wait
```

数据库自动从版本 7 升至 8，旧订单保持原样，新增独立的续期申请表。旧版本应用不支持版本 8，回退需恢复升级前的数据库备份及对应源码，不直接在新数据库上运行旧程序。刷新浏览器加载前端。

接口：用户 `GET /api/me/renewal-plan`、`GET/POST /api/me/renewals`、`POST /api/me/renewals/:id/cancel`；管理员 `GET /api/admin/renewals`、`GET /api/admin/users/:id/renewals`、`POST /api/admin/renewals/:id/approve` 与 `.../reject`。


## 用户界面

登录页使用居中卡片，用户中心使用顶部导航、蓝色主按钮和浅色内容卡片，支持深色模式及手机布局。管理员默认进入管理后台，可点击顶栏「用户中心」切换；在用户中心的账户菜单可返回后台。仪表盘展示真实账号额度、有效期、当前套餐和流量重置时间。顶部的套餐续期、订阅、邀请及更多菜单均连接现有功能，没有模拟商店、付款或无效文档入口。

管理员续期订单使用服务端分页（每页20条，返回total与rows），待确认优先；用户自己的申请记录最多显示最近2000条。客户端在刷新/取消后核对已提交的请求编号，避免网络响应丢失后复用已取消的申请。
