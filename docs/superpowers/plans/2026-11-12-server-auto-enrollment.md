# Automatic server enrollment and XB-style management

User requirement: copy one installation command to a native node host; no manually copied credentials. The server appears online even with zero nodes. Create a logical node, choose its server, save, and configuration synchronizes automatically. Follow the supplied XB server table: name, online status, CPU/memory/disk, node count, last heartbeat, details/edit/delete. No Docker on node hosts.

Design: retain internal authenticated Machine/Node REST contracts, hide credentials in normal workflows. An administrator generates a 15-minute enrollment command. The command carries a short-lived capability; the native CLI generates and privately persists a fresh random machine credential before claiming it over HTTP(S). Claim is transactional and idempotent only for the identical candidate credential. Generating a replacement command does not revoke the running server; successful claim replaces its credential. Code and credentials never appear in response logs/query strings. Existing public HTTP deployments remain supported, HTTPS remains documented for production.

## Exact contracts

- POST `/api/admin/machines/:id/enrollment`, body `{}` -> `{machine_id,code,expires_at}`; admin/session/origin protected. Regenerating invalidates previous enrollment code, not current machine auth.
- POST `/api/server/enroll`, body `{machine_id,code,token}` -> `{ok:true,machine_id}`. Code is 32 random bytes base64url; token is client-generated 32 random bytes base64url. Database stores hashes only. First valid claim atomically updates machines.token_hash and enrollment.claimed_token_hash; retries require matching claimed hash AND current machine token hash. Expiry 15 minutes; invalid/expired code rejects, conflicting claimed credential rejects. Different machine cannot claim. Machine deletion cascades only enrollment record, never nodes/billing.
- PATCH `/api/admin/machines/:id`, body `{name}` -> `{ok:true}`. Existing GET machine list keeps `{id,name,node_count,last_report_at,status}`. Metrics: status.cpu percentage, status.mem/disk `{total,used}`, status.net `{in_speed,out_speed}`. Heartbeat <=45s online, otherwise offline; null = not connected. UI refreshes every10s with timer cleanup.
- Machine node discovery base_config push_interval=10,pull_interval=10; per-node configuration poll<=10s. Installation immediately reports a heartbeat before periodic sampling. Machine readiness is connectivity only, not per-logical-node health.
- Frontend `machineCommand(origin,id,code)` produces one complete `bash -c` command using pinned installer revision, `--mode machine --machine-id ID --panel ORIGIN --enrollment-code CODE`; no prompt-token or manual credential fields. Installer auto-detects fresh installation vs exact existing Machine reconnect.
- Native `caddyctl machine-enroll` reads code from environment (installer passes it), validates matching existing identity before claiming, persists candidate before network request, retries safely, updates only that identity's private credentials/config. Permanent credential is never printed or passed to external argv. Release v0.1.2-preview supports amd64/arm64 and shipped corresponding source/notices.
- Node create/edit UI requires server association, hides raw Node token response. Backend standalone Node contracts preserved for compatibility. No raw token modal on machine creation either.
- Node create/edit includes default landing and ordered domain/CIDR route controls populated from existing exits. GET `/api/admin/nodes/:id/exits` returns `{default_exit,rules}`. POST/PATCH node body accepts optional `exit_routing:{default_exit:number,rules:[{exit_id,domain_suffixes?:string[],ip_cidrs?:string[]}]}`; omitted preserves current route, default_exit=0 clears default. Node and routing save in one transaction; invalid/disabled/incompatible exit rolls back the entire node save. Existing standalone routing page remains available.

## Work split and validation

1. Backend (root): migration4 + enrollment endpoints + rename + transactional/replay/expiry/permission tests; polling metadata. Real PostgreSQL tests, race in CI, existing users/data preserved.
2. Frontend (dedicated non-overlapping files): server table/details/edit/delete/auto-command, no token copying or node token modal. URL/code command tests, actual browser workflow/desktop/mobile after integration.
3. Native node (separate repository): enrollment client/installer + immediate heartbeat/poll contract, meaningful Go HTTP/failure/retry/identity tests and shell tests. Reuse native release pipeline, bump version without overwriting v0.1.1-preview. No live host/service changes.
4. Integration (root): one independent whole-change review, required fixes with regressions; publish two PRs, follow Linux CI, publish native release first, then merge panel and verify public downloads. Provide one panel update command.

Review focus: concurrent claim/replay and permanent credential scope; lost claim response vs local write failure; unsafe existing installation or shared/inline credentials; automatic zero-node heartbeat and new-node discovery; source/release/installer version alignment; honest missing metrics vs fabricated zeros.
